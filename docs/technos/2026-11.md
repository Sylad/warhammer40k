## Régressions trouvées et corrections

1. **e2e locaux en échec après `playwright-core` 1.65.1** — les 8 fichiers de `npm run test:e2e`
   échouaient : `Executable doesn't exist at …/chromium_headless_shell-1255/…`. Cause : chaque
   version de playwright-core attend son propre build de Chromium. Correction en local :
   `cd frontend && npx playwright-core install chromium`. La CI n'est pas touchée : son cache de
   Chromium a pour clé la version de playwright-core et réinstalle le navigateur quand elle change.

Aucune autre régression : voir « Vérifications ».

## Node 20 → 22 LTS (L230, 2026-11-17)

Majeure n° 1 ci-dessus, appliquée : images `node:22-alpine` (backend : builder et exécution ;
frontend : builder), CI « Contrôles frontend » sur `node-version-file: .nvmrc`, `.nvmrc` à
22.23.5, `engines.node` `>=22.12.0` dans les deux `package.json`, `@types/node` aligné sur 22
(frontend 18 → 22, backend 24 → 22, pour ne pas typer des API absentes du runtime).

Régressions rencontrées : aucune dans le code. Seul écart : les `package-lock.json` réécrits par
npm 10.9.9 (celui de Node 22) perdent les champs `libc` des binaires optionnels (écrits par
npm 11) ; npm 10 ne les lit pas, `npm ci` installe donc les variantes glibc et musl des binaires
natifs (rollup, esbuild…), chacun choisissant la sienne à l'exécution. Sans effet sur les images.

Vérifié sous Node 22.23.5 / npm 10.9.9 : `npm ci` des deux côtés ; backend `tsc --noEmit`,
`nest build`, `npm test` 25 fichiers / 151 tests ; frontend `vitest run` (hors e2e) 169 fichiers /
1280 tests, `npm run build`, `npm run test:e2e` 8 fichiers / 94 tests,
`scripts/test-nginx-cache.sh` conforme ; `docker build` des deux images, conteneur backend
démarré (`node -v` v22.23.5, `/api/health` ok, `/api/factions` servi).
